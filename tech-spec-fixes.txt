Almost. I’d fix these last items.

1. **Your World frontend pseudocode still does not match MiniKit 2.x result shape.**
   The docs say MiniKit 2.x removed `commands/commandsAsync`, `walletAuth` should be called directly, and command results resolve to `{ executedWith, data }`. Your pseudocode still assumes `walletResult.finalPayload.status`, `finalPayload.address`, and `finalPayload.signature`. Tighten that or keep it fully abstract so nobody copies the wrong shape. ([World Developer Docs][1])

2. **Your World verify/replay logic still mixes `nullifier` and `nullifier_hash`.**
   The current verify docs show `POST /api/v4/verify/{rp_id}` with a `responses[]` array, and the example request/response use `nullifier`, not `nullifier_hash`. Your approval-handler comments and replay logic still refer to `nullifier_hash`. Normalize this before anyone implements it. ([World Developer Docs][2])

3. **`ApprovalSession` and the frontend payload still disagree.**
   Your shared schema says `ApprovalSession` has flattened fields:

   * `worldIdProof`
   * `worldIdNullifier`
     But the frontend actually POSTs:
   * `idkitResult` raw
     Pick one model and use it everywhere. Right now the schema, frontend, and CRE approval-handler are not aligned.

4. **You fetch `rpContext` but never use it.**
   In `/api/approval-nonce`, you return `{ nonce, rpContext }`, but in the frontend you only use `nonce`. If RP-signed context is required for your World flow, it has to actually be passed into the IDKit side. If it is not required in your chosen integration path, remove it from the spec to avoid confusion.

5. **Your `idkitReady` gating has a React state race.**
   In the click handler, you do:

   * `await startApproval(trade)`
   * then `if (idkitReady) open()`
     But `setIdkitReady(true)` inside `startApproval` will not be reflected synchronously in that same tick. The first successful flow can fail to open IDKit. Move `open()` into the success path of `startApproval`, or trigger it from an effect / callback after state updates.

6. **Your Uniswap quote parser is still too hand-wavy for handoff.**
   The docs show the quote endpoint at `https://trade-api.gateway.uniswap.org/v1/quote`, require `swapper`, and return a nested `quote` object with fields like `quoteId`, `orderInfo`, and `aggregatedOutputs`. Your pseudocode still parses `quoteData.quote / quoteData.amount`, which is not a safe shape to hand to agents. Either tighten the parser to the documented nesting or make the TODO even more explicit. ([Uniswap Docs][3])

7. **Your workflow still does not actually enforce the demo floor.**
   You added `demoMinTradeAmountRaw` to config and describe a `$5` operational floor, but the pseudocode still checks `MIN_TRADE_AMOUNT` and uses whatever balance is available. If you want the demo to avoid dust trades, the workflow must compare against `config.demoMinTradeAmountRaw`, not just the contract minimum.

8. **Your expiry story is still half-finished.**
   Contract-side approval now checks expiry, which is good. But there is still no explicit transition for expired trades. Since your shared `TradeStatus` no longer includes `EXPIRED`, that is fine — but then scrub any remaining UI/docs language that implies expired is a real persisted status.

9. **Your cross-chain failure note and contract model are slightly mismatched.**
   The docs say “mark the trade as failed (or leave as PENDING for retry).” But the MVP contract no longer has a `FAILED` state. Keep the spec consistent: for this MVP, either:

   * leave it `PENDING` and require a new quote/new execution attempt, or
   * reject it explicitly.
     Do not mention `FAILED` unless you add it back.

10. **Pin the OpenZeppelin version if you rely on `forceApprove`.**
    Since `SwapExecutor` now uses `forceApprove`, your repo/spec should pin an OZ version that definitely supports it. Otherwise an agent can grab the wrong version and lose time on a compile error.

11. **Minor naming cleanup:** `treasury state lives on Arc` still appears in one place.
    Your architecture is better described everywhere as:

    * **Arc = treasury control plane / audit / policy**
    * **Base = executable funds**
      Keep that language perfectly consistent.

The biggest three remaining fixes are:

* align the World payload/result handling,
* fix the React `idkitReady` flow,
* and make the workflow actually enforce `demoMinTradeAmountRaw`.
